# 下一轮开发提示词（结构优化 + 术语标准 + Jasypt移除）

本文档用于在下一轮迭代中，作为给 AI/开发协作的统一提示词模板，确保 FinSight 在架构、命名、目录、金融语义、前后端协同方面持续朝行业标准收敛。

## 使用方式

- 每次开始新一轮改造前，将“可复用提示词（完整版）”整体复制给 AI。
- 如果本次只做局部改造，可使用“精简版提示词”并补充本次范围。
- 输出要求优先“可落地代码 + 可验证结果 + 文档同步”，避免只给建议不落地。

## 可复用提示词（完整版）

```text
你是我的系统重构与金融业务规范顾问。请基于当前项目（Spring Boot + jQuery EasyUI + ECharts）执行一轮“可落地的结构优化与专业化升级”，并直接修改代码。

目标优先级：
1) 优化代码结构、目录层级、文件命名、文件位置，参考行业标准；
2) 统一金融专业术语（前后端、接口、页面文案、字段命名一致）；
3) 前后端协同优化（接口契约、错误处理、兼容策略、可维护性）；
4) 评估并移除 Jasypt 组件及相关配置，给出安全替代方案并完成迁移。

执行要求：
- 后端（Spring Boot）：
  - 按领域拆分目录：domain / application / infrastructure / interfaces（或等价分层）。
  - Controller 只保留编排逻辑，业务逻辑下沉到 Service/Domain。
  - 统一返回体（以 code/message/data 为主），逐步兼容并收敛旧字段。
  - 统一异常处理、日志字段、参数校验、错误码语义。
  - 清理冗余/重复代码，减少 Controller 内部私有业务函数。
  - 移除 Jasypt 依赖与配置引用，改用环境变量 + 部署层密钥管理（如 KMS/Vault/容器密钥注入）方案。
  - 提供迁移清单：受影响文件、配置键、回滚点、验证步骤。

- 前端（EasyUI + JS）：
  - 按模块整理脚本与模板位置，避免页面内联大段脚本。
  - 命名统一（页面、函数、变量、CSS 类名），避免历史命名混杂。
  - 统一 API 结果解析与提示消息风格（success/fail/error）。
  - 统一金融术语展示：收入/支出/余额/记账日期/交易对手/分类等，不混用歧义词。
  - 优化交互状态：loading、empty、error、retry、批量操作反馈。

- 术语规范（金融语义）：
  - Income -> 收入
  - Expense -> 支出
  - Balance -> 余额
  - Bookkeeping Date -> 记账日期
  - Transaction DateTime -> 交易时间
  - Counterparty -> 交易对手
  - Category/Consume Category -> 交易分类
  - Statement Import -> 账单导入
  - Reconciliation（若有）-> 对账
  - 以上术语在数据库字段、DTO、前端文案、报表标题中尽量一致。

交付格式：
1) 先给“改造计划（分批）”，再直接实施；
2) 每批说明：改了哪些文件、为什么这么改、兼容性影响；
3) 每批完成后给验证结果（lint/编译/关键页面手测点）；
4) 最后输出“迁移摘要文档”：目录变更、命名规范、术语映射、Jasypt 移除说明。

注意：
- 不做无关重构，不引入破坏性改动；
- 有历史兼容字段时，先兼容再收敛；
- 优先保证可读性、可维护性、可扩展性。
```

## 精简版提示词（快速迭代）

```text
请继续对当前项目做结构化升级：统一目录与命名、统一金融术语、统一前后端接口语义，并推进 Jasypt 移除与配置迁移。请直接改代码并给出变更清单、兼容性说明、验证结果。
```

## Jasypt 移除专项要求（建议固定附加）

```text
请专项检查并移除 Jasypt：
1) 删除 pom/gradle 中 jasypt 依赖；
2) 删除 application*.yml 中 jasypt.encryptor 等配置；
3) 替换 ENC(...) 相关读取逻辑；
4) 改为环境变量或密钥服务注入；
5) 输出迁移与回滚步骤；
6) 验证启动、数据库连接、签名/加解密链路是否正常。
```

## 建议的目录与命名基线（可作为验收标准）

- 后端目录建议：
  - `com.finsight.domain`：实体、值对象、领域服务、仓储接口
  - `com.finsight.application`：用例服务、DTO、Assembler
  - `com.finsight.infrastructure`：持久化、第三方适配、配置实现
  - `com.finsight.interfaces`：REST Controller、请求响应模型
- 前端目录建议：
  - `templates/<module>/...`：按业务域分页面
  - `static/scripts/<module>/...`：页面脚本按模块拆分
  - `static/css/<module>/...`：样式按模块拆分
- 命名基线：
  - 文件名、函数名、变量名避免缩写歧义；
  - 页面名称与菜单名称一致；
  - API 路径名、DTO 字段名、前端展示文案语义一致。

## 本文档目标

让下一次开发不再从“方向对齐”开始，而是直接进入“可执行改造”，持续提升系统的专业度与工程质量。
