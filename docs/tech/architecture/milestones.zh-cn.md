# 产品路线图与里程碑

语言: 中文 | [English](milestones.md)

> **愿景**：从“数字账本”走向“本地、智能财务顾问”。
> **执行策略**：由 AI 增强的敏捷开发（1 名工程师 + AI 结对）。

本路线图阐述了构建 FinSight 的战略路径。它强调**务实**，每个阶段都交付可感知价值，同时控制技术债务。

## 阶段 1：“智能”账本（现代化）
**目标**：把遗留 UI 改造成现代、响应式体验，让用户*愿意*每天查看自己的财务。

*   **价值主张**：“清晰与愉悦”。消除笨重界面的摩擦。
*   **关键交付**：
    *   [ ] **UI 重构**：以响应式卡片/网格替换遗留表格（移动友好）。
    *   [ ] **仪表盘 2.0**：可自定义组件（支出 vs 预算、净值趋势）。
    *   [ ] **智能搜索**：全局搜索栏（cmd+k）快速定位交易或设置。
    *   [ ] **质量门**：核心领域逻辑单测覆盖率 90%。

## 阶段 2：数据基础（采集与组织）
**目标**：为 10+ 年碎片化财务历史构建健壮的数据管道。

*   **价值主张**：“数据可信”。垃圾进，垃圾出。本阶段确保数据准确、统一、可信。
*   **关键交付**：
    *   [ ] **多源导入**：
        *   **支付宝**与**微信支付**标准化导入器（CSV 导出处理）。
        *   主流银行对账单解析器（PDF/Excel 支持）。
    *   [ ] **数据卫生管道（ETL）**：
        *   **去重**：智能识别导入重叠（如先导入 1–3 月，再导入 2–4 月）。
        *   **退款匹配**：自动将退款与原始消费关联。
    *   [ ] **组织框架**：
        *   **商户归一化**：将“STARBUCKS COFFEE SHA”与“星巴克北京”统一为“星巴克”。
        *   **标签系统**：在类别之外添加多维标签（如 `#出差`、`#可报销`）。

## 阶段 3：自动化引擎（效率）
**目标**：把数据录入与维护的手工工作降到接近零。

*   **价值主张**：“时间自由”。
*   **关键交付**：
    *   [ ] **自动分类规则**：
        *   基于正则的规则编辑器（“描述包含 'Uber' 则类别设为 '交通'”）。
        *   基于历史的“智能建议”。
    *   [ ] **固定支出检测**：自动识别订阅（Netflix、Spotify）与固定成本（房租）。
    *   [ ] **数据导出**：一键 JSON/CSV 备份（数据主权）。
    *   [ ] **隐私优先同步**：设备间本地网络同步（无云）。

## 阶段 4：本地智能（顾问）
**目标**：集成本地 LLM（如 Llama 3 / Ollama），实现自然语言交互。

*   **价值主张**：“理解你的钱”。会问，会答。
*   **关键交付**：
    *   [ ] **RAG 引擎**：为 LLM 本地查询建立交易历史索引。
    *   [ ] **“问 FinSight”界面**：
        *   *“我上个月餐饮支出与去年相比如何？”*
        *   *“展示 2024 年我最大的支出。”*
    *   [ ] **隐私护栏**：保证推理过程无数据离开本地网络。
    *   [ ] **洞察推送**：主动通知（“你的餐饮预算已超出 15%”）。

## 阶段 5：财务智慧（预测）
**目标**：从“报告过去”走向“规划未来”。

*   **价值主张**：“保障你的未来”。
*   **关键交付**：
    *   [ ] **蒙特卡洛模拟**：“如果我每月存 ¥2k，何时能退休？”
    *   [ ] **情景规划**：“如果我买一辆车，会如何影响现金流与 runway？”
    *   [ ] **财务健康分**：统一指标（0–100）跟踪流动性、储蓄率与债务。
    *   [ ] **资产配置**：投资组合再平衡建议。

## 🛠 工程标准（方法论）

为用小团队（用户 + AI）高效交付，我们坚持：

1.  **AI 优先开发**：
    *   利用 AI 生成样板、单测与重构。
    *   利用 AI 生成文档。
2.  **质量保障**：
    *   **不破坏构建**。主分支始终可部署。
    *   **TDD** 覆盖复杂财务逻辑（尤其是阶段 2 ETL）。
3.  **本地优先架构**：
    *   避免复杂微服务。优选单体模块化架构以便部署。
    *   开发用 SQLite/H2，生产用 MySQL。

## 📉 风险管理

*   **风险**：银行/支付宝数据格式变更。
    *   *缓解（阶段 2）*：解析器插件化，让社区可在不改核心代码的前提下贡献修复。
*   **风险**：LLM 幻觉。
    *   *缓解（阶段 4）*：严格提示、引用来源（展示用于计算的交易）、并加上适当提示说明。
